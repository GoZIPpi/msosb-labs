\## Описание проекта



Учебный стенд для выполнения лабораторных работ

по сетевой и информационной безопасности.



Виртуализация: Oracle VirtualBox 7.2.16.

ОС виртуальных машин: Ubuntu Server 24.04 LTS.



Основной стенд размещён на компьютере Вовы.



\## 1. Виртуальные машины



CLIENT:

\- IP: 10.10.11.10/24

\- Интерфейс: enp0s8

\- Сеть: client\_net



GATEWAY:

\- IP: 10.10.11.1/24 (enp0s8)

\- IP: 10.20.11.1/24 (enp0s9)

\- IPv4 forwarding: 1



SERVER:

\- IP: 10.20.11.10/24

\- Интерфейс: enp0s8

\- Сеть: server\_net



Каждая ВМ также использует временный

VirtualBox NAT на интерфейсе enp0s3.



\## 2. Запуск стенда



1\. Открыть Oracle VirtualBox.

2\. Запустить GATEWAY.

3\. Запустить SERVER.

4\. Запустить CLIENT.

5\. Дождаться загрузки Ubuntu.



\## 3. SSH-подключение



На компьютере Вовы в PowerShell:



GATEWAY:

ssh -p 2222 labadmin@127.0.0.1



CLIENT:

ssh -p 2223 labadmin@127.0.0.1



SERVER:

ssh -p 2224 labadmin@127.0.0.1



Подключения через 127.0.0.1 доступны

локально на компьютере Вовы.



Пароли в репозитории не хранятся.



\## 4. Проверка сети



На CLIENT:

ping -c 3 10.10.11.1

ping -c 3 10.20.11.10



На SERVER:

ping -c 3 10.20.11.1

ping -c 3 10.10.11.10



На GATEWAY:

ip -br address

ip route

sysctl net.ipv4.ip\_forward



Ожидаемое значение ip\_forward: 1.



\## 5. Сетевые сервисы



SERVER:

\- Nginx HTTP: TCP 80

\- Nginx HTTPS: TCP 443

\- DNS (dnsmasq): UDP 53

\- Тестовый SMTP: TCP 2525

\- SSH: TCP 22



SMTP запускается вручную при необходимости.



\## 6. Проверка HTTP и HTTPS



На CLIENT:



HTTP:

curl http://10.20.11.10/



HTTPS:

curl --cacert \~/lab.local.crt https://10.20.11.10/



Используется учебный самоподписанный

TLS-сертификат.



\## 7. Проверка DNS



На CLIENT:

dig @10.20.11.10 lab.local A



Ожидаемый IP: 10.20.11.10



\## 8. Анализ трафика



Захват производится на GATEWAY

программой tcpdump.



Анализ PCAP выполняется в Wireshark.



Исследуемые протоколы:

ARP, ICMP, DNS, TCP, HTTP, TLS, SMTP.



Проверено прохождение ICMP через GATEWAY:

TTL на client\_net: 64

TTL на server\_net: 63



\## 9. Документация



topology/ — схема и адресный план

report/ — модель угроз и отчёт

evidence/ — скриншоты, PCAP и журналы

configs/ — конфигурации стенда

scripts/ — вспомогательные скрипты



\## 10. Безопасность



Стенд используется исключительно

для учебных экспериментов.



Не публиковать:

\- пароли пользователей;

\- закрытые TLS-ключи;

\- приватные SSH-ключи.



Доступ из интернета к учебным сервисам

напрямую не настраивается.
